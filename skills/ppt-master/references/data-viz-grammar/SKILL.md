# Data Viz Grammar — 把数字变成论点（跨介质）

> 适用于**任何**“把数字变成图”的任务：PPT 数据页、HTML 看板/报表、Excel 图、matplotlib 出图、
> 信息图。规则的来源是 FT Visual Vocabulary + Datawrapper/Economist 图版 + Bertin 视觉变量 +
> Cleveland & McGill 通道有效性 + Knaflic WAyED。**工具的差异只影响“怎么画”，不影响“画什么、为什么”。**

触发词：画个图、做个看板、这张图怎么画、图表太丑、可视化、配图、趋势图、对比图、
chart、dashboard、plot、数据页、报表排版。

## When to Use

加载本 skill 的任何一条都算：

- 要画图 / 改图 / 评判一张图好不好（“这张图怎么画”“图表太丑”“重做一页数据页”）
- 做看板、dashboard、HTML 报表、周月报看板（不论自写还是套模板）
- Excel 出图、matplotlib 出图、PPT 数据页、一页纸信息图
- 拿不准该用哪种图（“这个数据用什么图好”）——先过 §1 五步门
- 审计别人的汇报/看板，要判断“图版是否还在 2020 卡片语言”

不适用：纯装饰图（实拍照片、插画、logo）、概念示意图（用 excalidraw 类工具）。

## 0. 铁律（一句话版本）

**先有论点句，再选图种，最后才画。** 没有论点的图不画；有论点的图只用一种强调色，其余全灰。

反面模式（在任何介质里都算失败）：圆角卡片网格 + 投影 + 多色 KPI 瓦片 + 名词短语标题 +
色块图例 + 无来源行。这不是“美不美”，是**读不出结论**。

---

## 1. 五步门（每张图 / 每个数据页都走）

1. **写论点句**：≤24 字，必须含数字或方向词（升/降/超/低/倍/最/首/差/转）。名词短语（“各基地成本情况”）＝没论点。
2. **判意图**：把句子归到九类之一（§2）。判不出来 → 这页该合并或删。
3. **选图种**：按意图查 §2 首选/次选；命中 `Skip if` 的候选直接出局。
4. **定页型**：`chart_insight_rail`（图 62% + 右栏 结论/证据/动作）为默认；`hero_number` 单个数字；
   `comparison_swing` 改前改后；`bridge_waterfall` 归因拆解；`table_with_trend` 明细带火花线。
   **同一种页型不得连排 3 页。**
5. **按 §3 画**，交付前跑 §7 门禁。

---

## 2. 九类意图 × 图种

| 意图 | 论点长什么样 | 首选 | 次选 | Skip if |
|---|---|---|---|---|
| **Deviation 偏离** | “7 月超目标 17%” | 双向条形 diverging_bar | 双向堆叠 / spine / tornado / 正负面积 | 基准含糊或全同号 → 普通条形 |
| **Ranking 排名** | “江阴垫底” | 横向条形 horizontal_bar | slope（两期名次）/ bump / lollipop | 只比 2 项 → 大字对比即可 |
| **Distribution 分布** | “38% 工单吃掉 79% 成本” | 直方图 / 点图 dot_plot | dot_strip / lorenz / pareto / box | 样本 <15 → 列点，别画分布 |
| **Change over time 时序** | “连续 3 月下降” | 折线 | 柱（离散期）/ 分面小图 / fan（预测）/ 日历热力 | 单一时间点 → 用占比或量级 |
| **Part-to-whole 构成** | “服务类占 62%” | 100% 堆叠 / mekko | 堆叠柱 / waffle / treemap / waterfall | 段数 >6 → 合并或改用排名 |
| **Magnitude 量级** | “是去年的 3 倍” | 条形 | isotype / 比例符号（差>10 倍）/ 平行坐标 | 差 <5% → 标注数字，不画图 |
| **Correlation 相关** | “修复率与时长反向” | 散点 | 气泡（第三维）/ 连通散点 / 热力 | 点 <8 → 标注数值表 |
| **Spatial 空间** | “内蒙集中 3 处” | 地图（率用面量/总量用符号） | — | 排名类问题 → 用条形，别用地图 |
| **Flow 流向** | “A→B 占 40%” | 桑基 / waterfall | — | 节点 >12 → 改表 |

结构性页面另用四类：`Framework`（框架图）/ `Process`（流程）/ `Table`（明细）/ `Narrative`（叙事页）。

⚠️ **时序图的横轴必须是连续时间轴，不能是「有记录的那些时点」数组。**
数据层常见把稀疏月份存成数组（16 个点横跨 30 个月），按下标等距连线会把 11 个月的空档
画成邻月宽度 —— 走势直接读反，而图本身看不出任何异常。**画之前先展开成连续序列、
无记录补 0（源表完整则无记录＝无事件），再按连续轴取 x**；补轴后标签数会翻倍，
X 轴必须按槽宽抽稀且首尾保留。

| 意图 | 一句话判据 |
|---|---|
| 要读者看出「谁在涨、谁在跌」 | 时序 → 多线；**不要用堆叠柱**（见 §9） |
| 要读者看出「构成占比变了没有」 | 构成 → 100% 堆叠 / 份额折线；段数 >6 先合并 |

**多系列时序的系列数上限 = 5–6 条**，超过就取 TOP5 + 其余合并为「其他」，不要画全量。
注意 §3.4「单一强调色」在 6 条线时会退化成六条同色线：此时区分**靠端点标签 + 固定灰阶序列**，
不靠每条线一个饱和色（那是把颜色当编号用，违反 §4 表达性原则）。
绝对值互相遮挡看不清时，给一个「绝对值 / 占比」切换让读者自己换视图 ——
**占比视图是份额折线，仍属折线族，不要因为「要看清构成」就换回堆叠柱**。
两条都必须画在**同一条连续时间轴**上，切换只改分母不改 x 轴，否则两个模式下的走势不可比。

## 3. 十二条图版规则（跨介质通用）

1. **无容器**：不画卡片背景、不投影、圆角 ≤4px、不整页染色。白纸 + 发丝线。
2. **只留一种基线**：横向发丝网格（`#DAD7D0`）；无 Y 轴线、无刻度短线。
3. **直接标注**：系列 ≤4 时把名字写在端点，**不用色块图例**。
4. **单一强调色**：全图只有一个饱和色，落在标题指向的元素上；其余中性灰（灰/近白不算强调色）。
5. **参考线必带标签**：目标/基准虚线 1.5px + 右端说明。裸横线禁止。
6. **最多一个标注气泡**（≤14 字，8px 引线，指向具体元素）。第二个 → 拆页。
7. **数字只标论点相关项**：柱 >12 根时只标首、末、峰谷。
8. **补题即结论**：数字或方向词必须在标题里；单位/口径放副标题。
9. **来源行必填**：`数据来源：… ｜ 口径：…`；自算的数写“本团队测算”。
10. **两种字重**（400/600）；数字右对齐、千分位；单位在副标题出现一次。
11. **调色板**见 §6；**有序数据禁用色相**（用明度梯度/位置）。
12. **留白优先于装饰**：边距 ≥72px（1280 画布），8px 网格，删掉不承载论点的东西。

标注三连（每页最多两种）：行内标签（替代图例）→ 参考线（目标/基准/均值）→ 一个判断句气泡。

---

## 4. 为什么（选图时的仲裁依据）

- **通道有效性**：位置 > 长度 > 角度 > 面积 > 颜色。要让人比大小，就用位置；颜色只做分组或强调。
- **表达性原则**：数据有序 → 通道也必须有序（位置、长度、明度梯度）。用不同色相表示“高/中/低”会误导。
- **WAyED 测试**：闭眼 3 秒再睁眼，第一眼落在哪？落在卡片边框/装饰 = 编码失败。
- **探索 vs 解释**：6 条线、全量散点、带 5 个控件的交互图 = 给自己看的，不能上页/上台。
  判据：**去掉一半元素，论点还成立吗？** 成立 → 删掉那一半。
- **标题串测试**：把全部页标题连起来读，读得通 = 论证链成立；读不通 = 页序或分页错了。

## 5. 介质适配（同一套规则，不同落法）

| 介质 | 怎么落地 | 细读 |
|---|---|---|
| **PPT / SVG 页** | 走 `ppt-master` skill：`references/visual-grammar-v2/`（intent map / editorial-style / page-archetypes / visual-encoding）+ `templates/charts/charts_index.json` 按 `intent` 过滤、优先 `era="editorial"` | `ppt-master` §5.0 五步门 |
| **HTML 单文件看板 / 报表** | 无卡片网格、无 box-shadow、发丝边框、直接标注、一个强调色、图表下方来源行；字体下限 12px（正文 14–16） | [`references/html-single-file.md`](references/html-single-file.md) |
| **matplotlib 出图** | 去 spines、去网格或只留横向、`ax.text` 直接标注、色板统一、`dpi≈200`、`bbox_inches='tight'` | [`references/matplotlib.md`](references/matplotlib.md) |
| **Excel 图** | 按意图选图种、禁 3D/阴影、字号 ≥10pt、来源行写在图下、条件格式只做色阶 | [`references/excel-chart.md`](references/excel-chart.md) |
| **信息图 / 一页纸** | 页型 + 大字数字（hero_number）+ 三条支撑证据；1920 画布尺寸 = 1280 体系 ×1.5 | `ppt-master` one-pager 捷径 |

## 6. 调色板与字号

```
ink      #1A1A1A     正文/标题
graphite #4D4D4D     次级文字
mid      #767676     注释/轴标
hair     #DAD7D0     发丝线/网格
wash     #F5F3EE     极淡底（仅表头/斑马纹）
s1       #2C5C7E     强调色（默认）
s2       #A8543C     s2t #A8442F（负向）   s3 #C1913B 文本色 #8A6118
s4       #3F6F5E     正向       s5 #6F5B7E      s6 #8E8B84 中性系列
顺序色阶  #F0EEE9 → #C7D3DC → #8FAABB → #527F98 → #2C5C7E（仅热力/面量）
```

字号阶梯（1280 画布 → HTML CSS px → 1920 画布 ×1.5）：标题 34 / 副标 15 / 正文 15–18 / 注释 12；
**任何介质下限 12**（HTML 12px、Excel 10pt、PPT 12px）。HTML 正文建议 14–16px。

## 7. 交付前门禁（可跑，不靠自觉）

| 产物 | 命令 | 通过标准 |
|---|---|---|
| SVG/PPT 页 | `python <ppt-master>/scripts/check_deck_viz.py <deck>/svg_output [--profile brand]` | exit 0；每页首行 `<!-- PAGE: archetype=… intent=… -->` |
| 图表模板库 | `python <ppt-master>/scripts/check_chart_lib.py --editorial-only` | exit 0 |
| HTML 看板/报表 | `python scripts/check_html_viz.py page.html [--profile dashboard]` | exit 0 |
| 任一产物 | 渲染/打开后**真的看一眼**（vision 或截图） | 标题与图内数字自洽、无压字 |

`--profile` 的含义：`editorial`（默认，报告页：一个页面一个论点）严格——饱和色 >3 告警、>5 报错；
`dashboard`（交互看板）——>6 告警、>9 报错，并把投影/产品名标题降为 warning（浮层与工具标题合法）。
**两个 profile 都不放过**：<12px 字号、多图页无来源行、卡片网格替代论证。
HTML 审计对纯文字页（无图无表）不要求来源行 —— 否则检查会变成噪声，人就会开始无视它。

### 7.1 改造已有产物（已在用的看板/报表）

新技能落地时最常遇到的是「已经做好的东西要按新规矩翻新」，不是从零画。做法：

1. **先跑门禁拿客观清单**，再分层改、**每层单独验收**（一次性改完会定位不到哪一层弄坏的）：
   A 零风险样式（字号下限 / 去投影 / 圆角 ≤4）→ B 色彩与图例 → C 结论化标题 → D 版式（hero_number / 去卡片）。
2. **D 层用 CSS 覆盖层**追加在 `</style>` 前，不回改老规则——出问题删掉那一段就连根回滚，老样式全在。
3. **改色彩只替换 `<style>` 块内**：对整个文件跑正则会把 JS 里的 `'#7d2e2e'` 之类换成
   `var(--wine)`，直接把调色板定义写坏（脚本不报错，图变黑）。调色板**保留变量名、只换值**，
   避免几百处引用全改。
4. **结论化标题先找现成的结论读数**：成熟看板多半已有一个实时算出来的结论 span（角标/`concl`），
   把它从「标题后面」挪到「标题位置」、名词短语降级为右侧图种说明即可——不用重写文案，
   而且数字会继续跟着筛选联动（写死就废了）。
5. **去卡片后必查两件**：① 分区靠发丝线+留白是否还分得清（并发页面逐页看截图）；
   ② 奇数个卡片的网格（如 5 张放 2 列）会留半行空白 → 改 `auto-fit,minmax()`。
6. 改完**同步改探针**：结构变了（`.kpi`→`.hero/.hi`、图例取消改端点直标），
   旧断言会红。断言要改成核新结构，不要为了让测试变绿而放宽断言。
   **换图种是最容易被漏掉的一类**：柱状图数 `rect`、折线图数 `path[stroke]` + `circle`，
   把堆叠柱改成多线后旧计数断言永远拿 0 或旧值 —— 断言要跟着图种换口径。
7. **用户指出一张图的图种不对 ⇒ 全件按 §2 逐张复核，不要只改他点名的那张**。
   老看板里同类缺陷往往不止一处（同一套绘制函数被复用）。复核单位是「这张图的论点意图」，
   不是「这张图有没有报错」—— 图都画得出来，错的是**用构成图回答趋势问题**这类意图错配。
   复核产出要能给用户一张对照表（页 / 图 / 意图 / 现图种 / 判定），他才好逐条下单。
8. **被问「这规矩哪来的」时，回引条目原文而不是口头解释**：把对应条目（意图表某行、规则某条）
   连同关键句一并贴出，并区分哪些是技能原文、哪些是我自己的表层推理 —— 后者要主动标明。

门禁是启发式的：真结论句（“我们为什么输”）会被误判成名词短语；4 个真并列点用卡片行是合法的。
**遇误报改标题或人工放行，不要删规则。**

## 8. 页面级 auto-reject（见到就返工）

名词短语标题 · 两个互不比较的图并排 · 饼图做时序 · 地图做排名 · >2 个无语义强调色 ·
数据页无来源行 · waterfall 不闭合 · “其他”是最大类 · 同页型连排 3 页 · 卡片网格 + 投影 ·
柱 >12 根还逐根标数 · 图例色块 + 直接标注重复 · 文字压图 · 单位混用（万元 vs 元同页混写）·
**堆叠柱讲多系列趋势**（下层序列被上层压平）· **稀疏时间轴按下标等距连线**。

## 9. 常见误用（比不知道更危险）

- **“品牌模板要求卡片”**：品牌只管颜色/页眉/字体；几何与标注仍按 §3。品牌 ≠ 卡片网格。
- **“这是内部数据，不用来源行”**：内部数据更要口径，否则三个月后没人知道分子分母。
- **“先画着看效果”**：先画形状会倒推结论。改稿成本远高于先写一句话。
- **“配色好看就行”**：颜色是通道，不是装饰。多色 = 暗示多个维度。
